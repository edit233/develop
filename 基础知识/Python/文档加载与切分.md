## 概述
构建知识库的第一步：把各种来源的原始文档**加载**成普通文本（Document），再**切分**成合适大小的知识片段（Chunk）。本大类覆盖：Document Loaders（BaseLoader/PyPDFLoader/MinerU）与 Text Splitters（固定长度、递归字符、结构感知切分）。

## 文档加载（Document Loaders）
企业真实场景中需要加载的文档类型多种多样：PDF、Word、Text、CSV、HTML、扫描件等。这些来源的数据格式、结构差异很大，而 RAG 更擅长处理普通文本，因此**不管哪种来源，都要先转成普通文本**才能存入向量库。

LangChain 提供了丰富的文档加载器（Document Loaders）：
- **Webpages**：网页内容，如 WebBaseLoader
- **PDFs**：PDF 文件，如 PyPDF、OpenDataLoader PDF
- **CommonFiles**：常见文件，如 TextLoader、CSVLoader
- **Social platforms / Messaging services / Productivity tools**：社交媒体、消息平台、生产力工具（Figma、GitHub、Slack 等）

### BaseLoader 与 Document
所有加载器都继承 `BaseLoader`，提供统一的 `load()` 方法：一次性加载所有文档，返回 `list[Document]`。

`Document` 是 LangChain 表示文档片段的对象，包含两个核心字段：
- `page_content`：文档内容
- `metadata`：元数据（来源、页码等）

### PyPDFLoader（简单 PDF）
加载 PDF 文件，依赖于 `pypdf`，由 `langchain-community` 提供支持。
**注意**：`langchain-community` 已不被 LangChain 官方维护、不再推荐使用，这里只做演示。

安装依赖：
```bash
uv add langchain-community pypdf
```

PyPDF 支持两种模式：
- `single`：整个文档作为一个 Document（可自定义页间分隔符）
- `page`：每页作为一个 Document

标准代码：
```python
from langchain_community.document_loaders import PyPDFLoader

# 初始化并配置文档加载器
loader = PyPDFLoader(
    file_path='resources/贵州茅台研报.pdf',
    mode="page",   # single: 整个文件作为1个Document；page：按PDF分页
)

# 加载PDF文件，得到 list[Document]
docs = loader.load()
print(f'文档数量:{len(docs)}')

# 每个 Document 都包含 page_content 和 metadata 两个属性
for i, doc in enumerate(docs):
    print(f"==============Doc_{i}=================")
    print("metadata = ", doc.metadata)
    print("page_content = ", doc.page_content)
```

局限：pypdf 对复杂 PDF（分栏、复杂表格、图文混排、扫描件）处理效果差，格式混乱。这类 PDF 需要专业工具。

### MinerU（复杂 PDF，推荐）
MinerU（上海AI实验室）是高精度中文及复杂文档解析专家，能处理左右分栏、复杂表格、图文混排、图片扫描件，支持 OCR。

**常见 PDF 处理工具对比**
| 维度 | Docling (IBM) | Marker | MinerU (上海AI实验室) | Unstructured |
|---|---|---|---|---|
| 核心定位 | 企业级多格式文档处理平台 | 轻量快速的 PDF/图像转 Markdown | 高精度中文及复杂文档解析专家 | 非结构化数据通用 ETL 预处理平台 |
| 去页眉页脚/版面分析 | 极佳 | 良好 | 极佳 | 良好（极端复杂排版可能错序） |
| 性能 | 综合均衡（论文基准 RAG 准确率 94.1%） | 最快（H100 约 25 页/秒） | 约 200 页/分钟 | 一般，可权衡速度与质量 |
| RAG 生态 | 深度集成 LangChain/LlamaIndex | 需手动处理输出 Markdown | 适合预处理流，需自行封装 | Pipeline 生态成熟 |

**结论**：商业友好的开源产品是 Docling、MinerU、Unstructured；处理能力最强的是 Docling 和 MinerU，其中 **MinerU 是国人开发，速度与精度俱佳，推荐使用**。两者均可本地部署（追求最佳性能需 GPU、本地视觉模型、OCR、CUDA），适合数据隐私要求高的企业。MinerU 还提供公共 API、桌面客户端、SDK：每天免费处理 5000 个不超过 200 页的文档，小于 20 页不限数量。

**MinerU API 的两种模式**
- 🎯 **精准解析 API**：需申请 Token，支持单文件/批量、表格/公式/多格式输出，页数 ≤ 200
- ⚡ **Agent 轻量解析 API**：免登录、IP 限频，专为 AI Agent 工作流设计，页数 ≤ 20

**配置 TOKEN**：在 `.env` 中添加 `MINERU_TOKEN=sk-xxx`，然后在 Pydantic 配置中增加配置类：
```python
class RAGSettings(EnvSettings):
    """RAG相关配置"""
    mineru_token: str = Field(alias="MINERU_TOKEN")

# 在总配置 Settings 中挂载 rag 配置
class Settings(BaseSettings):
    rag: RAGSettings = Field(default_factory=RAGSettings)
```

**SDK 用法**（安装 `uv add mineru-open-sdk`）：
- Flash 模式（免 Token）：
```python
from mineru import MinerU

# 创建客户端，Flash 模式，无需 Token
client = MinerU()
# 解析文件
result = client.flash_extract("./resources/sample.pdf")

# 获取markdown
print(result.markdown)
# 保存到本地
result.save_markdown("./resources/r2.md")
```

- Precision 模式（需要 Token）：
```python
from mineru import MinerU
from app.core.config import settings

# 创建客户端，Precision 模式，需要 Token
client = MinerU(settings.rag.mineru_token)
# 解析文件
result = client.extract("./resources/sample.pdf")

# 获取markdown
print(result.markdown)
# 输出到本地，with_images=True 同时保存图片
result.save_markdown("./resources/r3.md", with_images=True)
```

- OCR（扫描件）：
```python
from mineru import MinerU
from app.core.config import settings

# 创建客户端，Precision 模式，需要 Token
client = MinerU(settings.rag.mineru_token)
# 解析文件，ocr=True 开启 OCR
result = client.extract('./resources/small_ocr.pdf', ocr=True)

# 获取markdown
print(result.markdown)
# 输出到本地
result.save_markdown('./resources/output/r4.md')
```

MinerU 不仅能处理 PDF，还支持 HTML、PPT、doc、xlsx、图片等多种格式，理论上一种加载器就能满足 99% 的企业需求。

## 文本切分（Text Splitters）
LLM 上下文窗口有限，不能把整个文档直接扔进去，需要切分成合适大小的块（chunk）。

**切分大小的权衡**（RAG 根据整个 chunk 的语义生成一个向量）：
- **chunk 太大**：包含过多无关信息，噪音多、语义不精准，检索精度下降；但语义完整度高。
- **chunk 太小**：噪音少、语义精准，检索精度高；但丢失上下文、语义不完整。

**常见切分策略对比**
| 策略 | 核心原理 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|---|
| 固定长度切分 | 按预设字符数/Token数切分 | 实现简单、速度快、可预测 | 易在句子中间截断，破坏语义完整性，或出现超大块 | 日志、代码等结构不敏感文本，或作为性能基线 |
| 递归切分 | 按优先级分隔符（段落 `\n\n` > 句子 `。`）逐级递归分割 | 尊重文档结构，语义完整，能动态调整 | 对无标准分隔符的文本效果下降 | **通用首选**，报告、文章等规范文档 |
| 语义切分 | 嵌入模型计算相邻句子相似度，低于阈值时切分 | 语义连贯性最好，分块质量高 | 计算成本高，依赖嵌入模型精度 | 学术论文、法律文件等高语义要求场景 |
| 结构感知切分 | 利用文档元数据（Markdown/HTML 标题）识别逻辑区块 | 天然符合文档组织逻辑，结构清晰准确 | 需要格式良好的文档，灵活性受限 | Markdown、网页等有清晰结构的文档 |
| 滑动窗口切分 | 固定窗口高重叠率（如 20%）滑动生成连续分块 | 上下文连接紧密，避免信息断裂 | 冗余度高，存储计算开销大 | 可与其他策略结合 |

### TextSplitter 接口
安装依赖：`uv add langchain-text-splitters`。

所有切分器实现统一接口 `TextSplitter`，提供两个最常用的方法（切分规则不同，用法大同小异）：
- `split_text(text)`：接收普通文本，返回切分后的文本列表 `list[str]`
- `split_documents(documents)`：接收 `Document` 列表，返回切分后的 `Document` 列表

### 固定长度切分（不推荐）
按预设字符数/Token 数切分，易在句子中间截断。

按字符切分：
```python
from langchain_text_splitters import CharacterTextSplitter

# 创建字符切分器
text_splitter = CharacterTextSplitter(
    separator="",        # 分隔符，空字符串表示任意位置都可分隔
    chunk_size=200,      # 每块最大200字符
    chunk_overlap=40,    # 块之间重叠40字符
)

# 切分文本
chunks = text_splitter.split_text(doc)

print(f"原始文本长度: {len(doc)} 字符")
print(f"切分为 {len(chunks)} 个块:\n")
for i, chunk in enumerate(chunks):
    print(f"--- Chunk {i+1} ({len(chunk)}字符) ---")
    print(chunk)
    print()
```

按 Token 切分（tiktoken，LangChain 自带编码器，无需额外安装）：
```python
from langchain_text_splitters import CharacterTextSplitter

# 使用 from_tiktoken_encoder 按 token 数量切分，更精确控制发送给 LLM 的 token 数
token_splitter = CharacterTextSplitter.from_tiktoken_encoder(
    encoding_name="cl100k_base",   # token 分词器编码名
    chunk_size=200,                # 每块最多200 token
    chunk_overlap=40,              # 块之间重叠40 token
)

chunks = token_splitter.split_text(doc)

print(f"原始文本长度: {len(doc)} 字符")
print(f"切分为 {len(chunks)} 个块:\n")
for i, chunk in enumerate(chunks):
    print(f"--- Chunk {i+1} ({len(chunk)}字符) ---")
    print(chunk)
    print()
```

### 递归字符切分（推荐）
`RecursiveCharacterTextSplitter` 是 LangChain 推荐的通用切分器，在不超过目标块大小的前提下尽可能保持段落和句子的完整性。

**关键参数**
| 参数 | 作用 | 默认值（通常） |
|---|---|---|
| `chunk_size` | 目标块大小（字符/token 计） | 4000 |
| `chunk_overlap` | 块间重叠长度，保留共同上下文 | 200 |
| `separators` | 分隔符优先级列表（控制分割行为核心） | `["\n\n", "\n", "。", ""]` |
| `length_function` | 长度计算函数（`len` 计字符 / tiktoken 计 token） | `len` |

**切割流程**：
1. 用当前优先级最高的分隔符（如段落 `\n\n`）尝试分割。
2. 遍历每个块：长度 ≤ `chunk_size` 则保留为最终块；大于则进入下一步。
3. 对"超大块"降级使用下一个优先级的分隔符（如 `\n`）再次分割。
4. 重复直到所有块 ≤ `chunk_size`。
5. 最终手段：所有分隔符都试过后仍超大的块，按 `chunk_size` 硬截断。

标准代码：
```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

# 创建递归切分器
recursive_splitter = RecursiveCharacterTextSplitter(
    chunk_size=200,
    chunk_overlap=40,
    separators=["\n\n", "\n", "。"]   # 优先级从高到低
)

# 切分文档
chunks = recursive_splitter.split_text(doc)

print(f"切分为 {len(chunks)} 个块:\n")
for i, chunk in enumerate(chunks):
    print(f"--- Chunk {i+1} ({len(chunk)}字符) ---")
    print(chunk)
    print()
```

### 结构感知切分
利用文档元数据识别文档本身的逻辑区块进行切分，如 Markdown 多级标题、JSON 字段、HTML 标签。LangChain 提供：`MarkdownHeaderTextSplitter`、`RecursiveJsonSplitter`、`HTMLHeaderTextSplitter`、`RecursiveCharacterTextSplitter.from_language()` 等。

标准代码（Markdown 为例）：
```python
from langchain_text_splitters import MarkdownHeaderTextSplitter

# 准备一段较长的文本
with open('./resources/评估.md', 'r', encoding='utf-8') as f:
    doc = f.read()

# 切分依据：按三级标题切分
headers_to_split_on = [
    ("#", "Header 1"),
    ("##", "Header 2"),
    ("###", "Header 3"),
]

# 创建切分器
markdown_splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on,
    strip_headers=False   # 文本中是否携带标题（False：正文保留标题）
)

# 切分文档，接收 str，返回值是 list[Document]
chunks = markdown_splitter.split_text(doc)

for chunk in chunks:
    print(chunk.model_dump_json(indent=2))
```

**注意**：`MarkdownHeaderTextSplitter` 并未实现 `TextSplitter` 接口，只有一个 `split_text` 方法，且只接收字符串、返回值一定是 `list[Document]`。

### 切分策略总结
没有绝对正确的切分方式，必须根据文档具体判断。如果使用 MinerU 这类输出 Markdown 的加载器，推荐：
- **优先按 Markdown 文档结构切分**：语义完整度高，且能记住知识片段所处的章节。
- **结构切分后块太大时**：对超过目标 size 的块再用**递归字符切分**，并把 header 保留到每一个分块。
- 也就是说，**可以把多种切分器混合使用**。
