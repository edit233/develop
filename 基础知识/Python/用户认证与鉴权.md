## 概述
用户身份认证的三件事（注册 / 登录 / 身份认证）、JWT 原理、密码哈希（pwdlib）、JWT 签发校验（PyJWT）、FastAPI Bearer 依赖注入的标准写法。适用于前后端分离项目（后端不保存登录状态）。

## 概念：注册、登录、身份认证
- **注册**：在用户表新增一条记录（用户名、邮箱、密码哈希）。
- **登录**：按账号查用户 → 校验密码 → 签发身份凭证。
- **身份认证**：每次访问受保护接口时校验凭证，得出「当前用户是谁」，失败返回 HTTP 401。

三者关系：注册解决「系统中有没有这个账号」，登录解决「证明自己是谁」，身份认证解决「后续每个请求到底来自谁」。

## 常见认证方案对比
| 方案 | 基本思路 | 特点 |
|---|---|---|
| Session | 服务端保存登录状态，客户端用 Cookie 携带 Session ID | 直观，但服务端有状态 |
| 普通 Token | 服务端生成随机 Token 并保存与用户的映射 | 仍需查询服务端状态 |
| JWT | 用户标识 + 有效期写入 Token，签名防篡改 | 自包含、无状态，适合前后端分离 |

## JWT 结构
JWT 由 `Header.Payload.Signature` 三部分用 `.` 连接：

- **Header**：token 类型与签名算法（如 HS256）
- **Payload**：用户信息（user_id、username）与 iat/exp 等；是 Base64URL 编码，**不是加密**
- **Signature**：用密钥对前两部分计算签名，校验内容是否被篡改

要点：
1. 签名 ≠ 加密，Payload 能被人还原，**禁止放密码、身份证号等敏感信息**。
2. 服务端校验至少做两件事：验证签名一致、检查是否过期。
3. 密钥绝不能泄露，不能硬编码进代码（放 .env，见下文配置）。

## 密码哈希（pwdlib）

依赖安装：
```bash
uv add "pwdlib[argon2]"
```

标准完整代码（core/security.py）：
```python
from pwdlib import PasswordHash

# recommended() 自动选用推荐算法（Argon2），并带随机盐
password_hash = PasswordHash.recommended()


def hash_password(password: str) -> str:
    """生成密码哈希：数据库只存哈希，绝不存明文"""
    return password_hash.hash(password)


def verify_password(password: str, hashed_password: str) -> bool:
    """校验密码：内部使用恒定时间比较，防暴力枚举"""
    return password_hash.verify(password, hashed_password)
```

要点：
- 明文密码只存在于请求处理过程中，落库前必须哈希。
- 登录时用户名不存在 / 密码错误 / 账号被禁用，应返回**同一个**错误（防止账号枚举）。

## JWT 签发与校验（PyJWT）

依赖安装：
```bash
uv add pyjwt
```

标准完整代码：
```python
from datetime import datetime, timedelta, timezone

import jwt

# 密钥与算法必须来自配置（.env），严禁硬编码
JWT_SECRET = "从配置读取"
JWT_ALGORITHM = "HS256"


def create_access_token(
    user_id: int, username: str, expire_minutes: int = 30
) -> str:
    """签名并生成 access_token"""
    now = datetime.now(timezone.utc)  # 时间统一使用 UTC
    payload = {
        "sub": str(user_id),  # 标准声明：主题（用户标识，规范要求字符串）
        "user_id": user_id,   # 自定义声明：业务里方便使用
        "username": username, # 自定义声明
        "iat": int(now.timestamp()),  # 签发时间（Unix 秒）
        "exp": int((now + timedelta(minutes=expire_minutes)).timestamp()),  # 过期时间
    }
    return jwt.encode(
        payload=payload,
        key=JWT_SECRET,
        algorithm=JWT_ALGORITHM,
    )


def decode_access_token(token: str) -> dict:
    """解析并校验 token：签名错误或已过期会抛 jwt.PyJWTError"""
    return jwt.decode(
        jwt=token,
        key=JWT_SECRET,
        algorithms=[JWT_ALGORITHM],  # 必须显式指定，禁止跟随 token 头部的算法
    )
```

要点：
- `exp` 必须是 Unix 时间戳（int 秒），校验时 PyJWT 自动检查。
- `algorithms=[...]` 显式白名单，防止算法混淆攻击。
- 密钥放配置（见下），一份密钥负责签发与校验。

## JWT 配置（pydantic-settings）

标准完整代码（追加到分层配置中）：
```python
from pydantic import Field
from pydantic_settings import BaseSettings


class JWTSettings(BaseSettings):
    """JWT 相关设置，全部来自 .env"""
    secret: str = Field(alias="JWT_SECRET")  # 密钥，必须配置且不进入代码/提交
    algorithm: str = Field(alias="JWT_ALGORITHM", default="HS256")  # 签名算法
    access_token_expire_minutes: int = Field(  # 令牌有效期（分钟）
        alias="JWT_ACCESS_TOKEN_EXPIRE_MINUTES",
        default=30,
    )
```

.env 对应配置：
```env
JWT_SECRET=换成随机长字符串
JWT_ALGORITHM=HS256
JWT_ACCESS_TOKEN_EXPIRE_MINUTES=30
```

## FastAPI Bearer 认证依赖

标准完整代码（dependencies.py）：
```python
from typing import Any

import jwt
from fastapi import Depends
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer

from core.security import decode_access_token
from 模块exceptions import 认证失败异常

# 提取请求头 Authorization: Bearer <token>；auto_error=False 表示缺失时不自动报错
bearer_scheme = HTTPBearer(auto_error=False)


async def get_current_user(
    credentials: HTTPAuthorizationCredentials | None = Depends(bearer_scheme),
) -> dict[str, Any]:
    """校验 Access Token，返回当前用户信息"""
    if credentials is None:
        raise 认证失败异常  # 401：缺少令牌

    try:
        payload = decode_access_token(credentials.credentials)
        return {
            "user_id": int(payload["user_id"]),
            "username": payload["username"],
        }
    except (jwt.PyJWTError, KeyError, TypeError, ValueError):
        raise 认证失败异常  # 401：令牌无效或已过期
```

受保护接口直接依赖注入：
```python
from fastapi import APIRouter, Depends

router = APIRouter(prefix="/api/v1/受保护资源", tags=["标签"])


@router.get("")
async def 列表接口(current_user: dict = Depends(get_current_user)):
    """没有有效 token 时，依赖注入阶段直接抛 401"""
    return {"当前用户": current_user["user_id"]}
```

## 注册 / 登录业务流（service 模式）

### 注册
```python
async def register(self, data) -> AuthResponse:
    # 1. 清洗并校验参数：username/email strip、密码最小长度
    # 2. 检查用户名或邮箱是否已存在 → 已存在抛 409（冲突）
    # 3. 创建用户：password_hash=hash_password(data.password)，只存哈希
    # 4. 签发 access_token（create_access_token(user.id, user.username)）
    # 5. 返回 {access_token, user}
```

### 登录
```python
async def login(self, request) -> AuthResponse:
    # 1. 校验参数非空
    # 2. 按用户名或邮箱查询用户（or_ 条件）
    # 3. 用户不存在 / status != "active" / 密码校验失败
    #    → 三者统一抛同一个 400 异常（防账号枚举）
    # 4. 签发 access_token
    # 5. 返回 {access_token, user}
```

### 认证异常（继承业务异常基类，见 [[日志与异常处理]]）
```python
class 认证失败异常(ApplicationError):
    """身份认证失败"""
    status_code = 401
    code = "UNAUTHORIZED"
    message = "缺少访问令牌，或令牌无效、已过期"


class 登录失败异常(ApplicationError):
    """登录认证失败：用户名/邮箱或密码错误"""
    status_code = 400
    code = "INVALID_CREDENTIALS"
    message = "用户名/邮箱或密码错误"


class 用户已存在异常(ApplicationError):
    """用户名或邮箱已被占用"""
    status_code = 409
    code = "USER_EXISTS"
    message = "用户名或邮箱已存在"
```
